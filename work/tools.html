How

I do not write code myself; I write the requirements. For every screen I decide how it should work and how it should look, then direct AI coding tools, revision by revision, until the result does both. Documents and films work the same way: the AI builds, I specify and check.

Work system

The AI works under standing rules: state only what has been verified, report before working, revise the latest version, check every deliverable. A memory carries decisions, formats and lessons from one session to the next. On that base sit the tools I use every day: a work-report tool, builders that generate decks, reports and screen specifications from scripts, minutes from transcripts, and HWP documents edited without opening the editor.

One case: this site

Fifty-five of my documents, in their original formats, became the gallery on this site through scripts I wrote with AI. The first renders every page as an image, drops any page that carries personal data, and records what each document is. The second writes the twelve pages of the site, in two languages, from that record. Another pulls every sentence out of the finished pages and compares the English with the Korean. I set the rules, chose the documents and checked the result; the AI wrote the code.

Rules

The standing rules, the same for every piece of work.

  1. State only what has been verified. Every sentence needs a source.
  2. Report before working. Say what will change, then change it.
  3. Revise the latest version. Do not start over without a reason.
  4. Check every deliverable for errors before it goes out.
